# DE Homepage — Operating Blueprint Static Material Specs

These are the exact static design specifications to use for the first review wall. They are deliberately separated from implementation code.

## HP-M01 — Aligned Operating Blueprint / 1440

Canvas: 1440×900.

Composition:
- graphite field (#050312) with warm-paper information strip occupying roughly the left 30–34%;
- the operating system occupies the remaining field as 8–10 translucent technical layers rather than a node cloud;
- layers share six visible registration anchors: PERSON, IDENTITY, POLICY, OBSERVABILITY, DOCUMENTATION, RECOVERY;
- relationship lines use no more than three hierarchy weights;
- security boundary is a continuous enclosure, not a shield icon;
- automation path is a distinct directional relationship, not a glowing circuit;
- DE appears once as the operating registration notation at the layer spine;
- violet is visible only as transmitted alignment light at shared anchors;
- magenta is limited to the DE action/registration accent.

Text zone:
- one large statement;
- one explanatory paragraph;
- tiny Oxanium labels only on real diagram metadata.

Must work as a standalone poster with zero animation.

## HP-M02 — Misregistered Operating Blueprint / 1440

Same canonical layer geometry as HP-M01, with intentional offsets rather than random chaos.

Visible misregistration:
- identity layer 18–24 px off the person/lifecycle anchor;
- endpoint layer 10–16 px off lifecycle/documentation;
- network/data layer crosses but does not terminate on observability;
- recovery layer does not connect to business-priority sequence;
- automation terminates at a manual handoff;
- security boundary is open at two domain transitions.

The composition should look competent-but-uncoordinated, not broken/glitched.

## HP-M03 — Layer system

Group the environment into these layer families:
1. People & Work
2. Identity & Access
3. Devices & Endpoint
4. Network & Connectivity
5. Cloud, Data & Collaboration
6. Security Controls
7. Business Systems
8. Automation & AI
9. Continuity & Recovery
10. DE Operating Cadence

Each layer must have:
- unique line pattern / depth cue rather than unique color;
- one short plain-English descriptor;
- one or two operating anchors;
- relationships to adjacent/non-adjacent layers.

## HP-M05 — Mobile / 390

Canvas: 390×844 target keyframe.

Do not shrink HP-M01.

Use five grouped translucent films:
1. People + Identity
2. Devices + Network
3. Cloud/Data + Business Systems
4. Security + Recovery
5. DE Cadence + Automation

The aligned state shows shared anchors down one vertical registration spine. Labels remain readable. Outcome selection changes which films/relationships are emphasized.

## HP-M20 — Operating cadence

Static service-blueprint direction:

OBSERVE → DECIDE → PROTECT → IMPROVE

Under that spine, show the supporting activity families only where canonically true:
- assessment / observation;
- documentation / evidence;
- remediation / change;
- monitoring / support;
- strategy / roadmap;
- verification / review.

The diagram should feel like an operating cadence, not a generic four-step marketing process.

## Review criteria

Before motion work:
- static aligned and misregistered posters should each score 18+/20 on the material-board scorecard;
- all five outcome states must remain immediately readable at 1440;
- mobile state must preserve the same argument without tiny labels;
- no fake telemetry, customer data, vendor marks, or fabricated performance claims;
- no generated people;
- the visual family must clearly belong to DE Visual System v2.
