# Dex integration (kit v1)

Dex is DE's public AI employee. Rati stays behind the scenes and is not part of this kit. This page says how
other apps show Dex: DE Desk, website chat, the Client Portal and the Intelligence Hub.

## What is in the kit

| File | What it is | Who uses it |
|---|---|---|
| `client/src/components/mascots/dexPresence.ts` | Emotions (`DEX_EMOTIONS`), the presence rules (`chooseDexPresence`) and `resolveDexLook`, which adds the holiday set | Anything that decides what Dex shows |
| `client/src/components/mascots/dexGeometry.ts` | Bars, poses for all nine emotions, holiday glyphs. No CSS, no React | Renderers |
| `client/src/components/mascots/holidays.ts` | 18 holiday sets, date rules, windows (`activeHoliday`, `nextHolidayWindow`) | Scheduling |
| `client/src/components/mascots/dexRender.ts` | `renderDexSvg(...)`: a static SVG string, no React | Email, Desk and Zoho templates, server pages |
| `client/src/components/mascots/Mascots.tsx` | `<DexMark />` for React, with a tween between emotions | The website |
| `dex/kit/dex-kit.json` | The whole kit as data, generated by `scripts/export-dex-kit.ts` | Apps that cannot run this code |

## How a consumer decides what to show

Build a `DexSignals` object from your own data and call `resolveDexLook(signals, new Date())`.

- `audience`: `client`, `prospect` or `public`.
- `phase`: `greeting`, `working`, `waiting`, `handoff`, `resolved`, `failed` or `idle`.
- `topic`: `security`, `outage`, `billing` or `general`.
- `urgency`: `0` to `3`. `3` is only for a live security problem or outage.
- `afterHours`, `surface` (`chat` or `email`), `composing`.

The result has `presence` (emotion, motion state, compact form, `mustHandOff`, and the reason in plain words) and
`holiday` (the set to show, or `null`). Show the reason in logs and reviews, not to clients.

Rules that always hold (tested in `dexPresence.test.ts`):

- Dex never shows "done" on a failed step, or on security or billing until a person has verified it.
- Security, billing, failures and handoffs always set `mustHandOff`. Dex never decides those alone.
- Extreme shows only for urgency 3 on security or outage.
- A holiday set never changes the emotion, and it is off when `mustHandOff` is set or urgency is 2 or more.

## Per app

**DE Desk (Zoho Desk).** Map the ticket's status and priority to `phase` and `urgency`, and its topic to `topic`.
Use `renderDexSvg` in reply and notification templates for the signature mark (`surface: "email"`, so the tile form
is used). A Zoho template is static, so it shows the resting pose of the mode. Keep Desk's own assignment rules as
the authority; Dex only reflects them.

**Website chat.** Set `phase` from the conversation: `greeting` on open, `waiting` when Dex asks a question,
`working` while it prepares a reply (`composing: true` for the typing form), `handoff` when a technician takes over,
`failed` when a step does not go through. Render with `<DexMark mode holiday state />`. The mode tweens between
messages; state (`thinking`, `speaking`) follows the reply.

**Client Portal.** Use the portal's ticket and project status for `phase`. The Portal is a separate repository:
copy `dex-kit.json` and `renderDexSvg` (or import the same files) and do not hand-copy the rules.

**Intelligence Hub.** Dex appears only where a client or DE staff member talks to Dex. Rati, the behind-the-scenes
employee, is not shown here. The Hub is a separate repository (`digeratiexperts/Intelligence-Hub`), so the same
copy-or-import rule applies.

## Holidays

The schedule is computed from date rules, so it needs no yearly edits. `activeHoliday(now)` returns the set showing
on that day, and `nextHolidayWindow(now)` returns the next one. The kit also lists the windows for 2026 to 2028.
The 18 sets are first drafts for review; a set is changed in `holidays.ts` and the kit is re-exported.

## Email

Many email clients strip inline SVG. For a signature, export a PNG of the static mark instead (an export step is
not built yet). Until then, `renderDexSvg` is for web pages and Zoho templates that accept SVG.

## Keeping it in step

1. Change the code under `client/src/components/mascots/`.
2. Run `npx tsx scripts/export-dex-kit.ts` to rewrite `dex/kit/dex-kit.json`.
3. Run `npx vitest run client/src/components/mascots`. The drift test fails if the JSON is stale.
4. If a rule's meaning changes, bump `DEX_RULES_VERSION`. If the shape of the JSON changes, bump `KIT_VERSION`.
