Three defects in the merged-in work, found and fixed here:

1. scripts/vendor-pdfjs.mjs could not run on Windows at all. It calls
   spawnSync("npm.cmd") without a shell, which Node 20.12+/22+/24 refuse
   (the CVE-2024-27980 fix) with EINVAL. Since the script is wired to
   `prebuild`, `npm run build` was dead on Windows. Fixed by routing the
   .cmd shim through the shell; tar still spawns directly.

2. The same script then failed extracting: it passed tar an absolute
   Windows path, and GNU tar (the tar on PATH under Git Bash) reads the
   drive-letter colon as a remote host:path spec. Fixed by extracting from
   inside the temp directory with a relative archive name, which is
   unambiguous to both GNU tar and bsdtar.

3. client/public/vendor/pdfjs/ was not gitignored, so a build left 2.5 MB
   of generated vendor JS staged as source. Added to .gitignore.

AUDIO ASSET — 2026-08-31

client/public/audio/digerati-pronunciation.wav is now committed and AUDIO_SRC
points at it, so the full-word button plays a fixed file instead of whatever
voice the visitor's browser happens to ship.

Provenance (it is synthesis, not a human recording): Windows SAPI, Microsoft
Zira, rate -3, driven by SSML carrying an explicit IPA phoneme string
"ˌdɪdʒəˈrɑːti" rather than the spelling. Trimmed to speech with 40 ms padding,
peak normalised to -1.5 dBFS. 16-bit PCM mono, 22.05 kHz, 0.849 s, 37,494 B.

The phoneme tag was verified as honoured rather than ignored: synthesising the
same word with a deliberately wrong phoneme (kæt) produced 0.439 s against
0.705 s for the plain spelling and 0.655 s for the correct IPA. A synthesiser
ignoring the tag would have produced the same length all three times.

Verified in a real browser against the production build:
  GET /audio/digerati-pronunciation.wav          200, 37,494 bytes
  decodeAudioData                                 0.849 s, mono, peak 0.841
  .wav requested when "Hear it" is clicked        yes — the recording plays,
                                                  synthesis is not reached

WAV rather than MP3 because no MP3 encoder exists on this machine; the only
ffmpeg present is Playwright's video-only stripped build, which cannot even
demux WAV. 37 KB of click-loaded media was judged a better trade than adding
an encoder dependency. Re-encoding to MP3/Opus would reach roughly 10 KB.

A new test, "points AUDIO_SRC at an asset that actually ships", fails the build
if the file is renamed or deleted. Without it that regression is silent: the
component falls back to synthesis and the button still makes a sound, just a
different one on every device.
